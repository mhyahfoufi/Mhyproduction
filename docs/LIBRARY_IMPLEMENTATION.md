## البنية المنفذة

- `assets/library-index.js`: معرّفات الأعمال وأسماؤها البديلة، ربط العناصر، وفهرس الصور الست المعلّقة على R2 كمسودات.
- `assets/library-model.js`: يجمع الفهرس والكتالوج السابق دون تعديل بياناته التي تستخدمها ملك؛ يستبعد المسودات وحلقات المسلسلات غير المنشورة.
- `assets/library.js` + `assets/content.css`: بطاقات أغلفة، أقسام ← أعمال ← ملفات، بحث عربي/إنجليزي، تشغيل YouTube والصور ودعم مشغلات الصوت والفيديو المباشرة.
- `library.html`: بحث عبر جميع الأقسام، `storyboard.html`: الستوري بورد، `media-library/index.html`: توجيه المكتبة القديمة.
- صفحات الأقسام العشر تعتمد العرض الجديد؛ الصفحة الرئيسية تحفظ الإعلان أولاً وتضيف البحث وجديد الاستوديو. الجديد يُرتّب بتاريخ `publishedAt` إن وُجد، وإلا يوضح ترتيب الإضافة للفهرس دون اختلاق تواريخ النشر.
- متابعة الفيديو المباشر اختيارية على الجهاز، بلا تتبع أو إرسال بيانات. تُحذف كل المواضع عند إلغاء الخيار وتُهمل بعد 30 يوماً. متابعة YouTube لم تُنفذ؛ تحتاج IFrame API وتجربة إضافية.

## R2: ما تحقق وما بقي

نفس Worker: `https://long-resonance-69a2.mhyprodection.workers.dev`. يدعم PNG/JPEG/WebP/MP4/WebM، حجم أقصى 25 MiB، قراءة عامة، ورفع بمفتاح محمي وإنشاء فقط دون استبدال. لا يدعم الصوت أو أفلاماً كبيرة أو مصادقة مالك من المتصفح.

آخر رفع للصور الست في Actions (run 42367479368) فشل بخطوة الرفع، واختبار سابق تجريبي نجح (42365709031). أُعيد إنتاج السبب محلياً: التعبير النمطي المتكرر للتحقق من base64 يُسبب `RangeError: Maximum call stack size exceeded` على الملفات الأصلية بحجم نحو 4 MB. عُولج في `upload.mjs` مع فحص canonical base64، واختبار ملف 4 MiB. ملفات الصور الست الأصلية اجتازت التحقق المحلي بعد الإصلاح. لم يُشغّل الرفع على main ولم تُعتبر الصور منشورة؛ يلزم إعادة الرفع باستخدام الإصلاح ومطابقة القراءة والبصمة قبل اعتماد النشر.

فحص `/health` من بيئة التنفيذ أعاد HTTP 403؛ لا يكفي وحده لتشخيص حالة الخدمة أو إعدادات الحساب. لا ندّعي اكتمال الربط الحي.

مسار التخزين الجديد: `mhy-media/<section>/<workId>/<unique-file>.<ext>`. المسارات القديمة `mhy-media/images/al-qarar-al-mustahil/...` محفوظة كما هي؛ العرض يعتمد category وworkId وليس مسار R2. لا نقل للملفات أو إنشاء مخزن جديد. ممنوع وضع أصول الأفلام الكبيرة في GitHub أو مفاتيح الرفع في الواجهة.

## إضافة عمل وإدارة خاصة

قبل إنشاء عمل، تستخدم `resolveWork` تطبيع العربية والأسماء البديلة؛ المعرّف ثابت مهما تغيّر العنوان. الأعمال غير المعروفة تحتاج اعتماد معرّف واحد وإضافة أسمائها البديلة، ثم اختيار القسم. كل نوع يبقى بقسمه الرئيسي دون مجلدات صور داخل مجلد الفيلم.

سير العمل الآمن للمرحلة المقبلة: إضافة سجل مسودة بالمعرّف والقسم → رفع أصل عبر الخادم المصرح → التحقق من القراءة والبصمة → اعتماد النشر وتحديث `status` و`publishedAt`. مفاتيح الرفع تبقى في Secrets الحالية. الفهرس لا يحمّل الملفات الأصلية إلى GitHub.

لم تُنشأ لوحة إدارة أو واجهة رفع عامة. تتطلب اللوحة مصادقة مالك على الخادم (مثل Cloudflare Access مع تحقق JWT)، وAPI للمسودات والنشر وفهرس محمي، وCORS مضبوط للعنوان المعتمد. تحميل الأفلام الكبيرة يحتاج رفع multipart مصرحاً وروابط قراءة مناسبة. يمكن تطوير نفس Worker وربطه بالمخزن الحالي؛ التكلفة تتعلق بخطة المصادقة والاستهلاك الفعلي، ولا يمكن تأكيدها دون بيانات الحساب. لا خدمات مدفوعة ولا تغييرات حساب قبل تقديم عرض تكلفة وموافقة المالك.
